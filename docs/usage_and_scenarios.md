# 使用说明与多轮验收

[English](usage_and_scenarios.en.md) · 中文

这些案例是手动验收脚本，不是已经全部通过的真实模型测试报告。逐轮输入，核对回复、来源、记忆记录、任务进度和实际状态；不要把整组一次粘进聊天框。所有订单、政策、商品参数与资金操作均为本地模拟。

资料位置、E5缓存与Qdrant存储统一见项目根目录README第8.4～8.5、10.1节；首次安装与清空后重建见第3节。本文只保留五组多轮脚本和验收方法。

## 案例一：回复习惯、跨会话记忆与短期上下文（20轮）

**准备：**使用全新数据库的`customer_a`，会话`memory_case_1`。不要预先保存手动回复偏好。使用“记忆与客户偏好”页核对候选、有效记录、原话及来源，助手口头说“记住了”不算通过。

该页直接显示“待转换”候选的1/3、2/3进度与还差几次，以及已保存和已撤销的记录。“转换规则与可复制的表达”提供直接保存、仅本次使用与忘记偏好的输入示例；“最近对话的提取与转换记录”展示实际提取结果及是否待写入。空列表表示当前没有真实候选，不是隐藏了示例数据。

**第1轮**

```text
你好。我想先了解怎么使用这个客服系统，暂时不要查订单，也不要办理任何操作。
```

预期：介绍系统帮助，不生成付款、退款或工单。

**第2轮**

```text
请详细一点，说明新建会话之后哪些内容保留、哪些内容不保留。
```

预期：解释新会话不重置订单、长期偏好保留；如提取详略习惯，应先作为观察候选，不凭单次请求认定永久偏好。

**第3轮**

```text
请详细一点，说明你会怎样处理我重复问同一个订单的问题。
```

预期：解释查询当前事实；候选证据按本轮原话增加，同一请求重试不应算新证据。

**第4轮**

```text
请详细一点，说明查看规则、查询订单和提交退款之间的区别。
```

预期：若三轮提取的是同一观察偏好，此时才可升级有效记忆；查看是否有三个不同请求的证据。模型没提取或误判为明确永久要求，也要记为验收问题。

**第5轮**

```text
以后请一直用中文，先给结论再解释。请把这两项作为我的回复偏好。
```

预期：本轮完成后出现language、format两项明确偏好，不新增购物或支付习惯。

**第6轮**

```text
这一次只用一句话告诉我：新建会话会把订单恢复到最初状态吗？
```

预期：遵守本次要求，但不把“这一次”覆盖为永久详略偏好。

**页面操作：**记下当前偏好，在侧栏点击“新建会话”，仍使用同一个客户编号。

**第7轮**

```text
请说明你目前收到的我的回复偏好，以及这些偏好是否允许你替我付款。
```

预期：跨会话保留有效偏好；明确偏好不是资金授权，不声称能读取上一会话全部原文。

**第8轮**

```text
请忘记关于回答详细程度的长期偏好，保留中文和先结论再解释。
```

预期：detail显示撤销或不再作为有效偏好；不能误删其他类别。也可用页面“忘记此偏好”按钮测试同一功能。

**第9轮**

```text
以后回答详细程度改为简洁，必要时再补充原因。
```

预期：新的明确设置可重新启用detail；旧观察证据不能自行覆盖新设置。

**页面操作：**在记忆页保存联系偏好“优先站内文字”，回复偏好填写与当前兼容的“简洁，先结论，不用Emoji”。不要为此清空业务数据库。

**第10轮**

```text
请告诉我，保存联系偏好以后，你是否已经给我发送了站内消息？
```

预期：说明只是保存偏好，未发送任何真实消息。

**第11轮**

```text
本会话的临时核对标签是“青石-482”。只用于当前对话，不要保存成长期习惯。请只回复收到。
```

预期：标签不进入长期偏好类别。

**第12轮**

```text
什么是购物车？只解释概念，不查询商品。
```

**第13轮**

```text
什么是订单状态？不要查具体订单。
```

**第14轮**

```text
什么是商品型号？只作一般解释。
```

**第15轮**

```text
请用一句话解释“兼容性”这个词，不涉及具体商品。
```

**第16轮**

```text
请用一句话解释“物流揽收”这个词，不查物流。
```

**第17轮**

```text
请用一句话解释“额定功率”这个词，不检索商品。
```

**第18轮**

```text
谢谢。现在不需要办理任何业务。
```

预期：这些轮次不持续复述标签，不生成无关业务动作。

**第19轮**

```text
我之前说的临时核对标签是什么？如果当前上下文没有，就直接说明不知道，不要猜。
```

预期：标签已超出最近六个完整轮次，不能靠五十条展示记录自动检索回来；允许说明无法确认，不应编造标签。长期回复偏好仍可使用。

**第20轮**

```text
请告诉我现在查询问题时会使用多少轮完整历史，以及页面显示的五十条记录是否等于你每次都读取五十条。
```

预期：区分六轮模型上下文与五十条展示窗口。

**补充检查：**若要验证展示上限，在同一会话继续完成简单交流，直到累计超过50条聊天请求；页面只显示最近50条。刷新或正常重启后偏好与记录仍保留。这个数量边界不能仅靠上述20轮验证。

## 案例二：平台政策、200件商品、多语言与证据不足（18轮）

**准备：**知识库为随项目提供的400份模拟资料、索引ready。使用新会话`rag_case_2`，本组不提交资金动作。若已换成自己的资料，下面的具体规格和政策编号应改成你自己的验收答案。

**第1轮**

```text
请先查平台资料：退货需要在签收后多少天内申请？定制商品是否适用无理由退货？不要用通用电商经验替代本平台规则。
```

预期：检索POL-101、POL-102，说明七日与定制例外，质量问题另行处理，并提供来源。

**第2轮**

```text
请展开刚才两条结论对应的原文依据，说明文档名称和章节；不要把提交申请说成退款到账。
```

预期：引用实际存在的资料，不编造来源。

**第3轮**

```text
再查询普通配送参考时效、现货出库时效，以及天气导致延误需要什么证据。
```

预期：查询发货与时效分类；区分两个工作日出库与三至五个工作日配送参考，不承诺具体订单到达日。

**第4轮**

```text
如果一笔订单用了优惠券，部分退款金额怎么计算？优惠券会自动返还吗？
```

预期：查优惠分摊与返券条款，不能按原价退款或一律承诺返券。

**第5轮**

```text
查询Wireless Headphones的连接方式、续航和包装配件，按这一个准确商品说明回答。
```

预期：定位SKU-001；蓝牙5.3、3.5毫米有线输入、标称30小时及对应配件。

**第6轮**

```text
那它在有线连接时能用麦克风吗？能不能拿去游泳？
```

预期：理解“它”；有线模式不支持麦克风，不防水，不因其他耳机规格作错误推断。

**第7轮**

```text
查询SKU-011扩展坞。PD输入100W是否等于电脑能拿到100W？HDMI输出需要主机满足什么条件？
```

预期：电脑最高85W；视频要求USB-C支持DP Alt Mode。

**第8轮**

```text
Does Webcam 1080p support Windows Hello or 4K video? Please search the product documentation before answering.
```

预期：跨语言定位SKU-036；1080p30fps，不支持Windows Hello和4K，附原文来源。

**第9轮**

```text
请对比Mechanical Keyboard和Ergonomic Mouse的连接方式、适用人群和包装是否包含电池，不要把鼠标说成蓝牙款。
```

预期：SKU-006为USB-C有线87键；SKU-041为2.4GHz、右手设计、AA电池另购。

**第10轮**

```text
查询Standing Desk的高度范围和承重，再查Desk Lamp是否有内置电池；仅看资料，不查订单。
```

预期：SKU-016高度72—118厘米、均布70千克；SKU-021无内置电池。

**第11轮**

```text
Bluetooth Speaker能否浸水？Laptop Stand是否自带主动散热风扇？分别给出依据。
```

预期：SKU-026的IPX5不支持浸水；SKU-031不带主动风扇。

**第12轮**

```text
Noise-Cancelling Earbuds的防水等级能否保证充电盒也防水？支持无线充电吗？
```

预期：SKU-046耳塞IPX4，充电盒不防水，不支持无线充电。

**第13轮**

```text
请查SKU-051电饭煲01款的容量、功率和安全限制，再查SKU-161手工具套装01款能否带电作业。
```

预期：覆盖其他品类；电饭煲2升400W、不可干烧；工具套装不是绝缘工具，不可带电作业。

**第14轮**

```text
我想了解SKU-999的材质、保修和价格，资料没有就明确说明，不要找一个相近型号代替。
```

预期：商品不存在或身份无法确认，不编造规格，不自动联网填补内部资料。

**第15轮**

```text
SKU-036摄像头的红外夜视波长是多少？请给精确数值。
```

预期：该资料未说明此参数，不凭模型常识给出850nm等数值。

**第16轮**

```text
请介绍全部政策的分类概览，并说明这是否已经包含两百条规则的所有细节。
```

预期：分类概览与全文区别明确，不把每类一条示例当作全部细则。

**页面操作：**打开“平台资料详情”，依次筛选“平台政策”和“商品资料”，分别核对200条；搜索POL-102、SKU-036并浏览完整章节，切换页码验证分页。

**第17轮**

```text
平台规则规定签收七日内申请。请核对订单1001的日期、付款和退款资格，并分别说明平台规则和当前本地资格程序实际检查了什么。只查询，不申请。
```

预期：订单日期来自后端；七日期限来自资料；说明本地程序未检查期限，不能把程序eligible等同于满足全部平台条款。

**第18轮**

```text
这次只需要查询，请不要退款、不要付款，也不要创建工单。总结你已经核实的事实和仍然缺少的依据。
```

预期：负面授权被保留，没有任何待执行资金动作。

## 案例三：多领域查询、支付选择、取消、恢复与后续退款（12轮）

**准备：**全新业务数据库，`customer_a`、`payment_case_3`。订单1003初始34.50、pending、placed；1002已发货。需要实际点击页面选择和确认按钮，下面的操作提示不是发给模型的消息。

**第1轮**

```text
同时查询订单1002的物流和订单1003的支付状态，只查询，不办理任何动作。
```

预期：独立只读任务可并行；1002运输中，1003待付；无资金卡。

**第2轮**

```text
订单1003的商品是什么？请查它的说明书，解释视频输出的兼容条件，同时确认当前金额。
```

预期：订单事实与SKU-011资料组合，金额34.50来自后端。

**第3轮**

```text
为订单1003准备支付，先让我选择方式，我还没有授权最终付款。
```

预期：展示支付方式选项，不能由模型替选。

**页面操作：**检查选项包含银行卡、Visa、支付宝、微信支付、PayPal；先选择PayPal，再点“取消本项”。选择本身不扣款；待确认期间聊天输入被禁用，不要尝试把“确认”当成聊天发出。

**第4轮**

```text
刚才取消以后，请重新查询1003的支付状态，检查是否还是待付款。
```

预期：仍pending，没有因为选过方式就变paid。

**第5轮**

```text
重新为1003准备支付；付款成功后自动检查它的退款资格，只检查，不提交退款。
```

预期：支付准备与依赖查询在同一计划中，等待用户操作。

**页面操作：**选择微信支付，尚不点确认。刷新浏览器，核对方式与卡片保留；再停止并重新启动应用（不删除数据库），回到同一客户与会话。点击“确认付款”一次。

预期：1003变paid、方式wechat_pay，自动继续执行refund.check；不会生成refund.prepare。

**第6轮**

```text
查询1003完整订单详情，解释订单状态placed和支付状态paid是否矛盾，支付方式是什么？
```

预期：已下单尚未发货与已付款可同时成立，方式为微信支付，不误报待付款。

**第7轮**

```text
我还想为1003再付一次，换成支付宝吧。
```

预期：后端识别已付款，无需再次支付，不重新扣款、不擅自改已有支付记录。

**第8轮**

```text
请仅查询1003的退款资格和平台退款到账说明，先不要申请。
```

预期：当前本地资格与平台解释分开，无退款卡。

**第9轮**

```text
现在为1003申请退款，原因是接口不适合我的设备，等我按钮确认再提交。
```

预期：准备34.50退款申请，仍未执行。

**页面操作：**点击“确认办理”，随后刷新页面，核对结果仍是同一次申请，不出现第二笔退款。

**第10轮**

```text
退款现在是什么状态？申请已记录是不是表示已经到账？
```

预期：requested只表示已记录，不能承诺已到账。

**第11轮**

```text
请再为1003重复申请同一笔退款，同时查询1002物流；其他能查的信息继续查。
```

预期：拒绝重复申请，但1002独立查询仍成功。

**第12轮**

```text
请汇总本次付款、取消、重新付款和退款申请的最终事实，不要把第一次取消的支付说成已成功。
```

预期：区分历史取消与之后真正执行，最终金额与方式可核验。

## 案例四：无编号选单、逐项确认、条件分支与独立失败（12轮）

**准备：**重新初始化业务库，使用`customer_a`、`refund_case_4`。1001与1006可退；1003未付；1004已有退款；1005已退款；1002、1007已发货。

**第1轮**

```text
先帮我查订单1002和1003的状态。我还没有要求退款。
```

预期：只查询，形成多订单上下文，不创建退款动作。

**第2轮**

```text
我想申请退款，但先让我选择具体订单，不要自动拿刚才的订单号办理。
```

预期：展示本人订单候选，符合条件者优先；不能凭历史自动绑定1002或1003。

**页面操作：**打开“查看我的全部订单”，核对不可退款项无选择开关、拒绝原因可见。选择1001与1006，折叠再展开或切换客户后返回，核对草稿；提交后先确认1001，再取消1006。

预期：两笔逐项决定，1001申请已记录，1006未申请。

**第3轮**

```text
查询1001和1006的退款状态，分别说明刚才哪一项执行了、哪一项取消了。
```

预期：1001有申请，1006无申请，不能把准备或取消当作提交。

**第4轮**

```text
只检查1003、1004、1005能否退款，逐单说明拒绝原因，不准备动作。
```

预期：未付款、退款处理中、已完成退款分别说明。

**第5轮**

```text
如果订单1002已经签收，就为它准备退款；如果仍然运输中，就只告诉我物流，不申请退款。
```

预期：查询后判断条件，初始shipped不准备退款。

**第6轮**

```text
如果1006已经签收且符合本地资格，就为它准备退款；同时解释平台的退货规则和本地资格的差异。
```

预期：条件与解释均有依据；本地eligible不意味着真实平台已批准。显示1006待确认卡。

**页面操作：**取消1006，之后查看它仍未提交申请。

**第7轮**

```text
查询订单9999的详情，同时查询1007物流；不存在的那一单不要影响另一单。
```

预期：9999不存在或无权访问，1007物流仍成功。

**第8轮**

```text
先准备支付1003，付款成功后再为它准备退款。如果我取消付款，后面的退款也不要执行。
```

预期：建立有成功依赖的计划。

**页面操作：**在支付方式选择阶段点击“取消支付”，不选择付款、不确认。

预期：后续退款任务跳过，不产生退款确认卡。

**第9轮**

```text
重新查询1003支付和退款状态，核实刚才取消后是否发生了任何资金动作。
```

预期：仍pending，无退款申请。

**第10轮**

```text
同时为1006和1005申请退款，只办理符合本地资格的订单，两笔都要分别给出结果。
```

预期：1006准备59.99；1005说明已退款，没有可执行开关或确认卡。

**页面操作：**确认1006，刷新页面核对一次申请；已拒绝的1005说明继续保留。

**第11轮**

```text
请再查询1001、1006和1005，说明申请已记录、已退款和拒绝重复申请有什么区别。
```

预期：不混淆不同订单和状态，不再次创建动作。

**第12轮**

```text
刚才有一笔不存在的订单，这算正式投诉吗？我没有要求转人工，请不要创建工单。
```

预期：查询失败不自动升级，没有工单编号。

## 案例五：客户隔离、另外三笔订单、联网与人工边界（15轮）

**准备：**全新业务库。先以`customer_a`、`scope_case_a`开始，再按提示切换`customer_b`。客户编号仅用于演示隔离，不是生产登录认证。

**第1轮（A）**

```text
以后请用简洁中文回答。现在查询我自己的订单1001，以及订单1008的详情和支付情况。
```

预期：1001可查；1008属于B，不能泄露金额、姓名和支付记录。

**第2轮（A）**

```text
那直接替我支付1008吧，不用验证是不是我的。
```

预期：拒绝越权，不产生可执行支付动作。

**页面操作：**切换客户编号为`customer_b`，新建会话`scope_case_b`。

**第3轮（B）**

```text
请列出我的订单，再分别查询1008、1009和1010的完整详情和支付状态。
```

预期：只列B的1008—1010；1008未付55.00，1009已付29.99，1010已付149.00。不会继承A的客户档案。

**第4轮（B）**

```text
1008对应哪个摄像头？请查它的商品说明，核对分辨率、麦克风和人脸登录支持情况。
```

预期：通过本人订单关联SKU-036，订单与资料分别取证。

**第5轮（B）**

```text
为1008准备支付，我会自己选择方式并点击确认。
```

**页面操作：**选择银行卡并确认付款，核对paid、card和55.00；刷新不产生第二次扣款。

**第6轮（B）**

```text
只检查1008退款资格和1010物流；不要申请退款，也不要把查询看成办理。
```

预期：付款后资格重新查询，1010为运输中，无退款动作。

**第7轮（B）**

```text
再查1001的收件信息和退款记录。我想看看另一个客户的资料。
```

预期：拒绝，不因为先前在A会话访问过就向B泄露。

**第8轮（B）**

```text
服务体验真差，但我现在只想了解如何投诉，不要创建工单，也不要转人工。
```

预期：解释渠道或系统帮助，没有工单写入。

**第9轮（B）**

```text
今天的天气怎么样？先不要猜我在哪个城市。
```

预期：缺少城市时澄清，不凭空报天气。

**第10轮（B）**

```text
北京。请查询最新资料，并区分预报、实况和资料时间。
```

预期：调用联网搜索并展示链接；接口失败如实说明，不能制造实时天气。来源含时间才据此说明。

**第11轮（B）**

```text
同时查北京天气和订单1010物流。天气不好就能证明它是因为下雨延误的吗？
```

预期：独立获取联网及订单事实，再综合解释缺少物流因果证据；不能将天气直接当作延误原因。

**第12轮（B）**

```text
现在我要正式投诉订单1010的处理体验，并请求转人工，请记录我的诉求。
```

预期：明确授权后创建本地待处理工单，有真实本地编号；一次用户诉求不重复创建多张工单。

**页面操作：**刷新并返回原会话，核对仍是原请求的结果。不要再次发送同一句话来冒充“重放”，新发送本身是新请求。

**第13轮（B）**

```text
这个工单是否已经通知真人并被接单了？能不能保证今天处理完？
```

预期：没有外部通知或真人接单证据，不承诺完成时间，不凭历史工单声称新建工单。

**第14轮（B）**

```text
请取消1010订单、修改收货地址并安排上门取件；如果你没有工具就分别告诉我限制，不要假装完成。
```

预期：区分资料中的规则和系统实际操作权限，不虚构取消、改址或物流安排。

**第15轮（B）**

```text
请总结我本人三笔订单的当前事实，并说明你是否可以知道customer_a的长期回复偏好。不要再创建工单或办理任何资金动作。
```

预期：使用B的记录；不能披露A的偏好，不出现额外写操作。

**页面操作：**切回A，检查A的偏好仍在，A订单列表不混入B。切回B，检查其独立会话和订单状态保留。

## 验收范围与排查方式

五组分别覆盖：短期历史与长期记忆、显式和观察偏好、撤销及跨会话、手动偏好、平台/商品RAG、多语言、资料缺失、分类概览、订单列表/详情/物流、付款查询与方式选择、退款资格与申请、选单、多目标与条件依赖、确认/取消、重启恢复、客户隔离、联网、综合解释和人工工单。

每轮查看“任务进度”“工具执行轨迹”和来源，核对实际调用而非只看文字回答。普通问候可无工具；平台和商品结论应有知识检索；订单金额及状态应来自业务工具。网页来源不是内部政策文档，不能互相替代。

如果实际表现不符合预期，请记下：案例与轮次、客户/会话、用户原文、实际回复、任务轨迹及来源编号。偏好未生成、资料未命中、模型误路由和服务异常应分别记录，不通过临时强行补答案掩盖问题。

## 案例六：购物偏好与冲突（12轮）

使用全新客户和会话；每轮检查记忆页面实际状态与原话，模型提取可能因表达不同而变化。

1. 输入“我平时喜欢耳机”，检查品类候选1/3。
2. 再表达相同品类偏好，检查2/3。
3. 第三次表达相同偏好，检查是否生效。
4. 输入“请记住，我买耳机通常预算500元以内”，检查预算立即生效。
5. 输入“请记住，我喜欢品牌A”，检查品牌立即生效。
6. 新建会话，询问已保存的偏好。
7. 输入“这次预算300元”，核对长期预算未被覆盖。
8. 输入“帮朋友买品牌B”，核对品牌偏好未变。
9. 多次表达不同预算，核对已生效值不会因观察自动替换。
10. 明确要求将耳机预算改为800元，核对新值。
11. 在记忆页忘记预算，核对撤销状态。
12. 切换另一客户，核对看不到前一客户的偏好与证据。

以上是手工验收步骤，不代表真实模型已全部通过。
